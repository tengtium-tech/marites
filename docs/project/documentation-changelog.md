DEC-014 answers how migrations are applied — a separate step with the migration credential, because the runtime role holds no DDL. AUD-052 |

| 0.9 | **The AI assistant.** DEC-015 records that Marites hosts a chat drawer on an adopter-supplied model, with a local runtime as a first-class and recommended choice. DOC-ARCH-004 §9 adds the second host — one tool registry, two transports — with the provider table, the payload switch and the four things the drawer must never do. VOCABULARY §17 adds the provider enum; DOC-UX-003 §3.9 and the route map add the drawer and `/ai`; FR-026 and TC-026 cover it. AUD-053 |

| 0.10 | **Live-only and storage after first run.** DEC-016 defines the mode an install runs in when storage is skipped: metadata and peek work, counts/history/audit/recovery do not. The wizard's storage step can be skipped, `/storage` adds or replaces a database later, and the consequence — **counts begin now, nothing before it was recorded** — is stated at the moment of enabling. Wireframes §3.10 and the banner states follow. AUD-054 |

| 0.10.1 | **Audit scope corrected.** FR-016 said "mutating operations", but the contract audits `peek` and `preflight` too — both touch the broker without changing anything durable. The requirement now states the real rule, the contract carries a description, and the audit screen's footer no longer says reads are excluded. AUD-055 |

| 0.11 | **Audit payload evidence.** DEC-017: history keeps what was sent or destroyed, as a snapshot in an eleventh table (`operation_payload`) on the capture retention clock — never inside the audit row, which is permanent. `GET /audit/{id}/payloads` and `ERR-AUD-001` when the evidence has lapsed; FR-027 and TC-027; wireframes §3.11 shows the expanded row and the expired state. THR-008 extended to cover the second place payloads can outlive their window. AUD-056 |

| 0.12 | **Complete and visible evidence.** DEC-018 supersedes DEC-017's sampling: one evidence row per message an operation touched, never a sample, and a replay stores both `payload_before` and `payload_after`. `operation_audit` gains `payload_edited`, written at the same time as the evidence, so an edited replay is distinguishable from a plain resend after the bodies have been swept. Wireframes §3.11 splits into two shapes — a single message shown whole with the changed lines marked, a batch listed message by message — and FR-027 and TC-027 assert both. AUD-057, AUD-058 |

| 0.13 | **A surface for the body.** Wireframes §3.11.1 adds the payload dialog: one read-only view for replay, discard, purge and publish, with a line-number gutter, side-by-side panes only when the body changed, a diff marked by both tint and `-`/`+`, and the hash and expiry in the footer. The expanded row becomes a summary rather than the record. AUD-059 |

| 0.14 | **Hold, command, record.** DEC-019 answers the atomicity question with a refusal: no transaction spans the broker and the store, so the guarantee is two invariants instead — no command without a durable copy of what it destroys, and no successful command left unrecorded. ADR-023 records the mechanism: `operation_intent`, a twelfth table holding the bodies, written and committed before the command and promoted to `operation_audit` + `operation_payload` on confirmation. The one non-atomic window is closed by reconciliation. `ERR-OPR-007` refuses an operation whose hold cannot be written; FR-028 and TC-028 assert both halves; wireframes §3.7 shows the bodies in the confirmation. AUD-060 |

| 0.15 | **Two stores, not one.** The storage decision was over-scoped: it made the adopter host all twelve tables when the requirement was to keep the messages. DEC-012 is revised — Marites keeps its own bookkeeping store (embedded SQLite, always present) and the adopter may connect a message store holding only `message_capture`, `message_rollup` and `capture_dedupe`. DEC-016 follows: skipping storage now costs **history, not recovery**, because the audit never depended on the adopter. ADR-022 amended, the data model split into §2.1 and §2.2, `capture_dedupe` kept with the messages so ADR-019's transaction still holds, and VOCABULARY now separates *recovery* from *restore*. AUD-062 |## Unreleased

| 0.16 | **Agent access propagated, and the wizard corrected.** DEC-010 and ADR-021 were revised last round but nine documents still said propose-and-approve: DOC-ARCH-004 now carries the full tool surface, the per-person credential with `CanExecute` (default off), the two paths and the new injection argument; FR-024, TC-024, `OP-OPR-007`, `ERR-OPR-005`/`006`, the `Approval-Id` description, `actorKind` and VOCABULARY follow. | 0.17 | **The traffic harness.** A new document, DOC-TEST-002, answers the gap the verification plan named against itself: 28 cases had no traffic to run against. It specifies a producer and a **rejecting consumer** — because dead letters only exist if something rejects — nine named scenarios, seeded determinism with a manifest that assertions read instead of guessing, three-provider parity where a scenario refuses to run rather than silently degrade, and four test-data rules. The verification plan's §5 fixture gap is closed as *specified*, not as *built*. AUD-064 |None.

| 0.18 | **Delivery and configuration.** Four documents close the gap between a specification and a project. DOC-OPS-007 records all fourteen `MARITES_*` variables with type, default and effect, separates what belongs in the environment from what belongs in the database, and states the startup validation rules — including why a missing message store degrades while a missing bookkeeping store is fatal. Deployment §3 gains the image, health and readiness, TLS and reverse proxy, and the log contract. AUD-065, AUD-066 |

| 0.19 | **The screenshots are a set, not a pile.** Thirty-five images captured from one build, with `screens/shoot.sh` committed as the record of every route. Capturing them exposed two prototype defects — the chat drawer was hardcoded to *no model connected*, so its configured state was unreachable, and the storage screen still claimed that connecting a database turns on replay, purge and the audit — both fixed and re-captured.
